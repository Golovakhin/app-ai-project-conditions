# Спецификации инструментов для работы с кодом (Цикл 2)

## 1. Инструмент: search_codebase
* **Назначение для LLM:** Ищет совпадения по ключевым словам в кодовой базе бэкенда. Используй, когда нужно найти, где определена функция, класс или переменная.
* **Параметры:**
  * `query` (str, обязателен): Строка для поиска (имя функции, класса и т.д.).
  * `limit` (int, опционально): Максимальное число результатов (по умолчанию 5, максимум 20).
* **Формат возврата:** JSON-строка. Успех: `{"status": "ok", "results": [{"file": "путь", "line": 10, "snippet": "текст строки"}]}`. Ошибка: `{"status": "error", "message": "описание"}`.
* **Краевые случаи:** Если ничего не найдено — возвращаем `{"status": "ok", "results": []}` (это не ошибка). Если `query` пустая — возвращаем ошибку.

## 2. Инструмент: read_file
* **Назначение для LLM:** Читает содержимое текстового файла из репозитория бэкенда. Используй, когда нужно изучить конкретный файл.
* **Параметры:**
  * `filepath` (str, обязателен): Относительный путь к файлу внутри репозитория (например, `src/main.py`).
* **Формат возврата:** JSON-строка. Успех: `{"status": "ok", "filepath": "...", "content": "..."}`. Ошибка: `{"status": "error", "message": "..."}`.
* **Краевые случаи (Безопасность):** Инструмент ДОЛЖЕН проверять, что путь находится внутри `AI_REPO_ROOT`. Если агент просит `../../.env`, файл не существует или выход за пределы репозитория — возвращаем ошибку `Доступ запрещен или файл не найден`.

## 3. Самый опасный инструмент (Пункт 6)
Самым опасным инструментом для агента является **read_file**. Хотя сейчас он только читает данные, без должных ограничений (проверки `AI_REPO_ROOT`) агент может прочитать системные файлы, переменные окружения (`.env` с ключами) или конфигурации. В будущем, если агенту дать право не только читать, но и исполнять код, ошибка в этом инструменте приведет к утечке данных или выполнению вредоносного кода.
